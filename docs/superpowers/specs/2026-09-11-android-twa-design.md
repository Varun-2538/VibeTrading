# Android app on Google Play via Trusted Web Activity

**Date:** 11 September 2026
**Status:** approved, implementing

## Goal

A VibeTrading listing on Google Play. The stated motivation is presence on the store,
not native features: no push notifications, no offline analysis, no iOS. The trading
panel already has a phone-first compact layout, so the app is the existing web panel
wrapped so that it installs and launches like an app.

## Decisions taken

| Question | Decision |
|---|---|
| Packaging | **Trusted Web Activity** generated by Bubblewrap. Chrome renders `app.vibetrading.club` full-screen with no browser UI. Rejected: Capacitor (native surface we do not need), React Native (rewrite; charts would still be a WebView). |
| What the app opens | `https://app.vibetrading.club/` — the panel, not the landing page. |
| Wallet on Android | **Add WalletConnect** alongside the injected connector. Android has no extension wallets, so without it the sign-in button is dead. Reverses the "injected only" decision in the wallet-identity spec; the cost there (a third-party project ID) is now justified. |
| Orientation | Portrait only. The compact layout is portrait-first and landscape is untested. |
| Push notifications | Out of scope. Web Push works inside a TWA on Android, so this shell does not need replacing to add it later. |
| Play account | Personal account. Production is gated on a closed test with 12 opted-in testers for 14 continuous days. |

## 1. PWA-ready web app (`frontend/`)

A TWA is only accepted by Chrome and by Play review if the site is an installable PWA.
Four additions, no change to the panel's UI.

**Manifest.** `app/manifest.ts`, Next's typed route, served at `/manifest.webmanifest`.
`name` and `short_name` "VibeTrading", `start_url: "/"`, `display: "standalone"`,
`orientation: "portrait"`, `theme_color` and `background_color` taken from the panel's dark
palette in `globals.css`, `icons` at 192 and 512 px plus a 512 px `maskable` entry.

**Icons.** PNGs in `public/icons/` rendered from the candle mark in `app/icon.svg`. The
maskable variant keeps the mark inside the inner 80% safe zone on a solid background so
Android's adaptive-icon masks do not clip it.

**Service worker.** `public/sw.js`, precaches a single `/offline` page on install and
serves it when a navigation request fails. Nothing else is cached: a stale candle is
worse than an error, and the API sets its own cache headers. Registered once from a small
client component (`components/register-sw.tsx`) mounted in the root layout, guarded on
`"serviceWorker" in navigator`. `app/offline/page.tsx` is a static page in the panel's
palette saying the connection is gone and offering retry.

**Digital Asset Links.** `public/.well-known/assetlinks.json` declaring
`delegate_permission/common.handle_all_urls` for package `club.vibetrading.app` with the
SHA-256 fingerprint of the **Play App Signing** certificate. This is what lets Chrome
drop the URL bar. The fingerprint is only known after the first upload to Play Console
(App integrity page), so the file is committed with the upload-key fingerprint first for
sideload testing, then the Play fingerprint is added — both may be listed.

**Middleware.** `middleware.ts` rewrites every path on the app host onto `/app/…`. The
matcher gains exclusions for `.well-known`, `manifest.webmanifest`, `sw.js`, `offline` and
`icons` so those are served from the route tree and `public/` as-is.

## 2. WalletConnect (`lib/wallet.ts`, `hooks/use-session.ts`)

`lib/wallet.ts` adds `walletConnect({ projectId, showQrModal: true })` imported from the
`wagmi/connectors/walletConnect` subpath (present in the installed wagmi 3.x), after
`injected()` in the connectors list. `projectId` is `NEXT_PUBLIC_WALLETCONNECT_PROJECT_ID`;
a missing value at build time omits the connector rather than crashing, so local dev
without the ID still works with a browser wallet. `.env.example` documents it.

`startConnect` in `use-session.ts` currently takes `connectors[0]` and reports "No browser
wallet found". It now picks `injected` when `window.ethereum` exists and WalletConnect
otherwise; the error only fires when neither is available and its copy mentions mobile
wallets. On Android the WalletConnect modal deep-links to an installed wallet; the SIWE
signature request round-trips through the wallet app and back to Chrome. No backend
change: the nonce, message and verification are unchanged.

The privacy page's wallet section gains one sentence: connecting through WalletConnect
relays the session through WalletConnect's servers, which see the wallet address.

## 3. Android shell (`android/` at repo root)

Generated by `npx @bubblewrap/cli init --manifest https://app.vibetrading.club/manifest.webmanifest`.
Bubblewrap offers to install JDK 17 and the Android SDK on first run.

Settings in `android/twa-manifest.json`: `packageId: club.vibetrading.app`,
`host: app.vibetrading.club`, `startUrl: /`, `display: standalone`,
`orientation: portrait`, `themeColor`/`backgroundColor` matching the manifest, splash from
the 512 icon, `enableNotifications: false`, `fallbackType: customtabs`.

Committed: `twa-manifest.json` and the generated Gradle project. Ignored:
`android/app/build/`, `android/.gradle/`, `android/build/`, `android/local.properties`,
`*.keystore`, `*.jks`. The upload keystore lives outside the repo and its password in a
password manager; Play App Signing is enrolled at first upload so a lost upload key can be
reset without losing the listing.

`bubblewrap build` produces `app-release-bundle.aab` for Play and `app-release-signed.apk`
for sideloading. Each upload needs a higher `appVersionCode`; `bubblewrap update` bumps it
from `twa-manifest.json`.

## 4. Play Console

No code. Done in this order because later steps depend on earlier ones.

1. **Create the app** — name VibeTrading, app, free, default language en-IN or en-US.
2. **Upload to Internal testing** first: the fastest way to get the Play App Signing
   fingerprint and a pre-launch report. Copy the SHA-256 into `assetlinks.json`, deploy,
   verify with Google's statement-list tester before the next upload.
3. **Store listing** — short description (≤80 chars), full description from the README's
   "What it does", 512 px icon, 1024×500 feature graphic, at least two phone screenshots
   (1080×2400 from Chrome device emulation of the compact layout: chart, analysis,
   assistant), privacy policy URL `https://vibetrading.club/legal/privacy`.
4. **App content** declarations:
   - *Data safety*: collects wallet address (user ID; linked to user; required for rules;
     encrypted in transit; deletable on request to dev@vibetrading.club), and messages
     typed into the assistant (app activity; sent to a third-party LLM). No location,
     contacts, or advertising IDs.
   - *Financial features*: not a financial product — holds no funds, executes no trades,
     is not an exchange or wallet. Links to `/legal/risk`.
   - *Content rating* (IARC questionnaire): no real-money gambling, no simulated gambling;
     expected "Everyone" but target audience set to 18+.
   - *Ads*: none. *Government app*: no. *News*: no.
5. **Closed testing** — create a track, add an email list of at least 12 testers, share
   the opt-in link. They must stay opted in for 14 continuous days. Uploads during the
   test are fine.
6. **Apply for production access** from the dashboard once the 14 days pass. Google
   replies within about a week. Then promote the same bundle to Production.

## 5. Testing

- `npm run build` passes; the built site's Lighthouse PWA audit on
  `app.vibetrading.club` reports installable, valid manifest, registered service worker.
- `curl https://app.vibetrading.club/.well-known/assetlinks.json` returns the JSON with
  `content-type: application/json` (not the panel's HTML, which is what a wrong
  middleware matcher would produce).
- `bubblewrap doctor` and `bubblewrap validate` clean.
- Sideloaded APK on a physical Android phone: no URL bar after asset links verify,
  portrait locked, "Connect wallet" opens the WalletConnect modal → MetaMask mobile →
  signature request → rules panel unlocks; airplane mode → offline page; returning
  online → panel reloads.
- Desktop web unchanged: injected wallet still connects first; WalletConnect appears
  only as a fallback.
- Backend test suite untouched (no backend changes).

## Out of scope

Push notifications, iOS/App Store, landscape layout, offline caching of candles or
analysis, any change to the panel's screens.
